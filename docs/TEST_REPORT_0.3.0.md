## 新版 Studio 的实际操作

两种 Broker 版本执行 Topic 创建、列表、分页、路由、消费组查询、CSV 导出与删除；Group 创建、列表、分页、详情、订阅、进度、配置修改、导出与删除；实际发送 UTF-8 多行消息并验证自定义属性、按消息 ID 查询和队列浏览；真实消费者接收、位点预览与重置；集群和 Broker 配置差异、NameServer 差异、客户端与生产者列表；DLQ 列表。5.3.3 额外读取 ACL 用户和规则。

4.9.7 首轮测试发现新建消费组尚无持久化消费位点时，Broker 拒绝重置。测试夹具已改为真实订阅消费者并显式持久化初始位点，避免依赖 SDK 的定时提交时机；业务接口仍按真实 Broker 结果报告失败。Studio 测试同时检查外国实例 ID 被拒绝、官方页面使用当前实例名称查询可正常工作，以及全部登记写接口的只读保护。

旧 Dashboard 接口另有真实在线消费、DLQ 查询/导出/重发、消息轨迹、ACL 认证、SOCKS5 和故障测试。这些结果用于确认底层管理能力，不能替代新版每个页面交互的完整验收。

## 尚未完成的验收及已知限制

- Windows 7 + WebView2 109 实机运行、DBX 原生安装升级和文件保存未在本轮自动验证；编译与 PE 检查不代表实机兼容性验收。
- 新版 UI 的在线消费者全部诊断、消息轨迹、DLQ 重发和 Excel 导出、ACL 全部写入、多连接和真实 SSH 故障场景仍需逐项 UI 验收。
- 上游集群页面仍保留部分连接注册/K8s 控件，相关平台接口未接入；调用会明确报错。连接应在 DBX 表单配置。K8s、多云和通知平台不在本插件范围内。
- 旧后端的 Group 监控配置尚未接入新版 UI；ACL 凭据查看、策略身份修改仍需适配。
- 缺少 Broker 原始数据的创建/修改时间、今日消息数等显示无数据，不生成模拟数据。历史仅在保持连接期间采集。

本版本作为可审核、可安装验证的商店候选提交，不声明原计划全部业务入口已经完成验收。
